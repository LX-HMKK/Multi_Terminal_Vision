# 通信协议文档

三端之间的网络约定。默认端口沿用原项目，可用环境变量或代码覆盖。

## 1. 角色与地址

| 角色 | 载体 | 默认 IP | 说明 |
|---|---|---|---|
| 部署端（nano / 车） | Jetson Nano | `192.168.87.102` | 采集摄像头、控制小车 |
| 运算端（服务器） | 笔记本 / PC | `192.168.87.77` | YOLO 检测 + 跟踪 + 避障决策 |
| 上位机（Q 端） | Windows Qt | 同运算端（`127.0.0.1` 可达） | 可视化、记录、下发指令 |

> 运算端与上位机通常跑在同一台笔记本上，故上位机地址对运算端就是回环地址。

## 2. 端口一览

| 链路 | 协议 | 端点（监听方） | 默认端口 | 方向 |
|---|---|---|---|---|
| 视频 | UDP | 运算端监听 | `5552` | 部署端 → 运算端 |
| 视频 | UDP | 上位机监听 | `8888` | 运算端 → 上位机 |
| 指令/事件 | TCP | 上位机监听 | `9999` | 运算端 ↔ 上位机 |
| 指令 | TCP | 部署端监听 | `12345` | 运算端 → 部署端 |

> 原架构里部署端还主动连运算端 `4447`（`serve+yolo+detect.py` 的
> `handle_tcp_connection` 为空实现），属于**死代码**，本次重构已废弃删除。

## 3. 视频传输

- 部署端：摄像头0 → OpenCV 采集 → JPEG 编码 → UDP 单帧发送。
  单帧超过 `65500` 字节会自动降质重压，保证不超 UDP 上限。
- 运算端 → 上位机：标注后的画面同样 JPEG + UDP 回传。
- 上位机：`QUdpSocket` 绑定 `8888`，用 `QImageReader` 解码成 `QPixmap` 显示；
  收到 `ID_xx_*` 事件时保存当前帧为 `.jpg` 并登记到 SQLite。

## 4. 指令与事件（均为 ASCII 文本，部分以换行 `\n` 分隔）

### 4.1 控制模式（上位机 → 运算端 → 部署端）

| 字符 | 模式 | 部署端行为 |
|---|---|---|
| `0` | 自动循迹 | 黑线循迹自动控制 |
| `1` | 手动 WASD | 由 `w/a/s/d/f/g` 控制 |
| `2` | 避障 | 循迹为底，避障指令优先 |
| `3` | 关闭避障（恢复循迹） | 停止避障决策，回到循迹（**非停车**） |

> 紧急停车不是模式，而是避障动作 `stop`（见 4.3）或手动 `s`。
> 上位机四个按钮：`打开自动循迹→0`、`关闭自动循迹→1`、`打开避障→2`、`关闭避障→3`。

### 4.2 手动指令

| 指令 | 含义（串口帧首字节） |
|---|---|
| `w` / `a` / `s` / `d` / `f` / `g` | WASD 手动（`9/10/11/12/13/15`） |

### 4.3 避障动作（运算端 → 部署端，模式 2 时）

| 动作 | 含义 | 串口帧首字节 |
|---|---|---|
| `left` | 目标在画面右侧 → 向左绕 | `7` |
| `right` | 目标在画面左侧 → 向右绕 | `8` |
| `detour` | 目标在中央 → 绕行 | `5` |
| `stop` | 目标过近 → 停车 | `6` |
| `no` | 无行人/面积不足 | 不改变动作（继续循迹） |

### 4.4 目标事件（运算端 → 上位机）

| 事件 | 含义 |
|---|---|
| `ID_<id>_start` | 出现新跟踪目标，上位机保存当前帧 |
| `ID_<id>_end` | 目标离开画面 |

## 5. 串口控制帧（部署端 → 下位机）

固定两字节：`[signal, 0x43]`，`signal` 值见 `deployment/config.py` 的 `SIGNALS`。
不同模式语义不同，由下位机固件按当前模式解释。

| 语义 | 首字节 | 模式 |
|---|---|---|
| sharp_left / left / straight / right / sharp_right | `0/1/2/3/4` | 循迹 |
| detour | `5` | 避障 |
| stop | `6` | 避障/停止 |
| avoid_left / avoid_right | `7/8` | 避障 |
| w / a / s / d / f / g | `9/10/11/12/13/15` | 手动 |

> 说明：`left` 在循迹下是 `1`、在避障下是 `7`（即 `avoid_left`）。代码用语义名
> （`avoid_left`/`avoid_right`）区分，避免与循迹方向字节冲突。

## 6. 易于联调的做法

- 无需实体车也能跑通链路：运算端用 `--source synthetic`（合成帧）或 `--source webcam`；
  部署端用 `SERIAL_PORT=mock`。各连接为自动重连 + 日志打印，未接线不会卡死。
- 上位机需先启动并点击“开启监听”，运算端再启动（或等待重连成功）。

## 7. 安全（可选，默认可信局域网）

本项目为局域网课程演示，默认**不做鉴权**（信任局域网）。若部署到更开放的网段，建议：

- **部署端指令服务**默认只绑定 `NANO_IP`。若无法绑定（如开发机）则**拒绝启动**（fail-closed），
  绝不静默暴露到 `0.0.0.0`；开发联调请设 `COMMAND_BIND=127.0.0.1`（回环）或显式 `ALLOW_UNSAFE=1`（会告警）。
- **共享令牌（推荐）**：两端都设 `NANO_TOKEN=<secret>`（部署端与运算端一致）后，
  运算端连接时发送 `AUTH <token>`，部署端用 `hmac.compare_digest` 校验、失败 3 次即断开；
  令牌为空 = 默认信任局域网（启动会打印告警）。
- **加固建议**：可用防火墙限制 `12345/5552/9999/8888` 仅对可信主机开放；
  上位机收到的事件需按 `ID_<数字>_(start|end)` 白名单解析（代码已限定，只用数字 ID 命名截图）。
