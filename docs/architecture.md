# 系统架构

## 1. 总体

一套**多端协同的视觉避障与远程控制系统**（动量轮自平衡自行车 · 课程项目三）。

两端计算机 + 一辆小车，用“**UDP 视频 + TCP 指令**”贯通成闭环：

```
      摄像头0(视频)                 摄像头1(黑线)
         │                              │
  ┌──────▼───────┐              ┌───────▼───────┐
  │  部署端       │              │  部署端         │
  │  Jetson Nano  │              │  (控制线程)     │
  │  camera→JPEG  │              │  循迹→控制信号   │
  │  →UDP:5552    │              │  →串口→下位机     │
  └──────┬───────┘              └───────────────┘
         │ UDP 视频                          │
         ▼                                   │ TCP 避障指令 (运算端→部署端:12345)
  ┌────────────────────┐                     │
  │  运算端 (笔记本/PC) │─────────────────────┘
  │  YOLO检测+跟踪      │
  │  避障决策 left/right│
  │  /detour/no        │
  └───────┬─────┬──────┘
          │ UDP │ TCP
          │视频  │ 指令/事件
          ▼     ▼
  ┌────────────────────┐
  │  上位机 (Qt C++)    │
  │  UDP:8888 显示视频   │
  │  TCP:9999 收事件发指令│
  │  SQLite 记录+截图    │
  └────────────────────┘
```

## 2. 各端职责

### 部署端（`deployment/`，Jetson Nano，Python）
- **图传线程**：摄像头0 → JPEG → UDP 发给运算端 `5552`。
- **循迹线程**：摄像头1 → 灰度化+阈值+腐蚀膨胀 → 统计左右黑像素 → 控制信号。
- **指令服务线程**：TCP 监听 `12345`，接收运算端指令（模式/wasd/避障）。
- **中央控制器**：按“模式 + 最近指令 + 循迹结果”决定当前串口下发的控制字节，
  统一经 `serial_bridge` 下发，避免原代码多线程直写串口的竞态。
- 串口抽象：`RealSerial`（pyserial，真机）与 `MockSerial`（仅日志，无硬件联调）。

### 运算端（`server/`，笔记本/PC，Python）
- **帧源抽象**：`server/sources.py`——`udp`（默认，来自 nano）/ `webcam` / `video` / `synthetic`，
  统一接口 `FrameSource` + 工厂 `build_source`。
- **检测与跟踪**：ultralytics YOLO（替代原 yolov5+SORT），一次性给出目标框 + 跟踪 ID。
- **生命周期事件**：新目标 `ID_xx_start`、消失 `ID_xx_end` → TCP 发上位机。
- **避障决策**：`avoidance.py` 纯函数——最大目标位置分区 + 面积阈值 → 左/中/右动作；
  `ActionThrottle` 做节流与“仅变化才发”，抑制抖动。
- **网络链路**：`server/net.py`——`TCPSender`（自动重连，向 nano / 上位机）、`UDPSender`（回传上位机）、
  `TrackState`（目标生命周期）、`HostCommandHandler`（解析上位机指令并转发）。未接线时自动重连并日志提示，不阻塞主循环。

### 上位机（`host/`，Windows，Qt Widgets C++）
- **视频显示**：`Udp_Thread` 收 `8888` → `QPixmap` 显示；模式由“开启监听”按钮控制。
- **指令/事件**：`Tcp_Thread` 监听 `9999`；接收事件、保存截图、回发 `0/1/2/3` 等。
- **数据库**：SQLite `messages.db`，记录保存的截图路径与时间（北京时间），支持 CRUD。

## 3. 关键设计取舍
- **跨端一致性**：三端共享同一套模式（`0/1/2/3`）与指令集，见 `docs/protocol.md`。
- **无需硬件即可联调**：运算端 `--source synthetic`、部署端 `SERIAL_PORT=mock`；
  所有连接自动重连，任一端未启动都不会让其它端卡死。
- **移除死代码**：原 `4447` 空连接、`yolov5`/`sort` 外部依赖、`getout.py` 空文件等，
  见 `docs/known-issues.md`。
